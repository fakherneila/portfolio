## Pourquoi ce blog existe

Je crée cet espace pour rendre visibles les raisonnements qui se cachent derrière mes réalisations. Un portfolio montre la surface finale, mais l’ingénierie intéressante se trouve souvent dans les décisions, les contraintes et les compromis.

J’y parlerai de développements techniques, de stratégie de tests, d’expérimentations en IA et machine learning, ainsi que des leçons tirées de mes stages. Certains articles seront pratiques; d’autres seront des réflexions sur ce qui a fonctionné, ce qui a échoué et ce que je ferais autrement.

### Ce que vous y trouverez

Les sujets tourneront souvent autour de quelques questions :

- Comment transformer un besoin produit flou en interface fiable ?
- Quels tests donnent réellement confiance à une équipe ?
- Où l’automatisation aide-t-elle, et où ajoute-t-elle de la complexité ?
- Que peut apprendre un étudiant en livrant un produit à de vrais utilisateurs ?

Un petit exemple du style de code que j’aime expliquer :

```ts
type Result<T> = { data: T; error: null } | { data: null; error: Error }

export function ok<T>(data: T): Result<T> {
  return { data, error: null }
}
```

> La bonne ingénierie consiste souvent à rendre la prochaine évolution plus facile à comprendre.

<Callout type="tip" title="À propos du format">
Les articles resteront concrets : schémas, extraits de code, cas de test et contexte nécessaire pour comprendre chaque choix.
</Callout>

Vous pouvez suivre les projets derrière ces notes sur [GitHub](https://github.com/). Merci d’être ici; j’espère que ces pages seront utiles, que vous soyez en train d’apprendre, de relire une décision ou simplement curieux de voir comment un produit prend forme.
